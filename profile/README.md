#### LLM usage policy

Tomori Lab follows the principles of [Responsible Use of Generative AI](https://www.debian.org/vote/2026/vote_002), adopted by Debian in its 2026 General Resolution. All contributions must meet the same standards of quality, correctness, maintainability, and legal compliance, regardless of whether generative AI tools, including LLMs, were used.

- **Human review and accountability**: Contributors must understand and review AI-assisted output, perform the necessary tests, and make any required changes. Contributors remain responsible for the quality and suitability of everything they submit.
- **Copyright and licensing**: Contributors must check the provenance and licensing of their output and exclude material whose legal status they cannot reasonably justify. Existing copyright and licensing requirements apply regardless of the tools used.
- **Disclosure**: Contributors are encouraged to disclose AI assistance. This policy does not require disclosure.
- **Confidentiality and privacy**: Non-public code, private communications, undisclosed security vulnerabilities, cryptographic keys, credentials, and other sensitive material must not be shared with third-party AI services without explicit authorization and compliance with the project's security and privacy requirements.
- **Large-scale automation**: Bulk issue or patch submissions and extensive automated changes require prior discussion and agreement through the appropriate project channels. A human must oversee and remain accountable for the process and its output.

#### Repository access

Access is assigned according to each contributor’s responsibilities, using [GitHub repository roles](https://docs.github.com/en/organizations/managing-user-access-to-your-organizations-repositories/managing-repository-roles/repository-roles-for-an-organization):

| Role | Typical responsibilities |
| --- | --- |
| Read | Follow development and participate in project discussions. |
| Triage | Help manage issues and pull requests without write access to code. |
| Moderate | Moderate discussions and manage issues and pull requests without write access to code. |
| Write | Contribute code regularly and help maintain the project. |
| Maintain | Coordinate development, releases, and routine repository management. |
| Admin | Manage repository settings and access when required for project administration. |

#### Organization membership

[Organization roles](https://docs.github.com/en/organizations/managing-peoples-access-to-your-organization-with-roles/roles-in-an-organization) are separate from repository access:

| Role | Membership criteria |
| --- | --- |
| Member | Contributors approved to collaborate on Tomori Lab projects. Repository and team access is assigned according to their work. |
| Owner | Trusted maintainers responsible for organization administration, security, and continuity. Ownership requires explicit approval from an existing owner. |

Contributions across multiple repositories may support a request for broader responsibilities. Membership and permission changes are reviewed individually; contribution counts or roles in other communities do not automatically grant access.
